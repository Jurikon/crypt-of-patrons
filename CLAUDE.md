# CLAUDE.md — Crypt of Patrons

## Проект

Crypt of Patrons: пошаговый рогалик от первого лица для браузера. Дизайн в `docs/GDD.md`, этапы в `docs/ROADMAP.md`. Владелец проекта не читает код: она проверяет работу игрой по критериям приёмки. Проект строится с прицелом на коммерческий релиз и кооп в будущем.

## Стек

- pnpm, Vite, TypeScript в режиме `strict`
- three.js для 3D, Preact для интерфейса поверх канваса
- Vitest для тестов симуляции, Playwright для smoke-теста сборки
- ESLint + Prettier
- Деплой превью: GitHub Pages через GitHub Actions на каждый push в `main`
- Новая зависимость добавляется только с объяснением в отчёте

## Структура

- `src/core/`: сидовый RNG, базовые типы, утилиты сетки
- `src/sim/`: состояние игры, команды, движок эффектов, ИИ врагов, генерация карты забега и комнат
- `src/content/`: данные классов, способностей, модификаторов, предметов, покровителей, врагов, биомов
- `src/render/`: сцена three.js, меши, камера, анимации событий
- `src/ui/`: HUD, меню, выбор наград, подсказки
- `src/input/`: преобразование клавиш и мыши в команды
- `src/i18n/`: `en.json`, `ru.json`
- `src/debug/`: дебаг-меню и оверлей
- `tools/`: безголовый запуск забегов, бот-балансировщик

## Жёсткие правила архитектуры

1. **`src/sim` и `src/core` не импортируют three.js, DOM, Preact, `render`, `ui`, `input`.** Это проверяет правило ESLint `no-restricted-imports`. Симуляция запускается в Node без браузера.
2. **Детерминизм.** В sim запрещены `Math.random`, `Date.now`, `performance.now` и итерация по объектам с неопределённым порядком. Вся случайность идёт из RNG, чей сид хранится в состоянии. Один сид и одни команды всегда дают один результат.
3. **Команды → события.** Состояние меняется только функцией `apply(state, command) → { state, events }`. Команды и состояние сериализуются в JSON. Рендер только читает состояние и анимирует события.
4. **Контент — это данные.** Способности, модификаторы, предметы и дары описываются типизированными объектами в `src/content`. В движке запрещены проверки вида `if (ability.id === ...)`. Если для нового контента не хватает возможностей, добавляется общий примитив эффекта, а не частный случай.
5. **Движок эффектов на событиях.** Небольшой набор примитивов (урон, толчок, телепорт, обмен, состояние, поверхность, призыв, лечение, щит, изменение ОД) и триггеры по событиям с фильтрами по тегам. Глубина цепочки срабатываний ограничена (по умолчанию 32), превышение логируется, а не вешает игру.
6. **Несколько игроков в состоянии.** В состоянии всегда массив игроков, даже если игрок один. Глобальных «текущий игрок» нет.
7. **Тексты только через i18n-ключи.** Никаких строк для игрока в коде.
8. **Сохранения с полем `version`** и функциями миграции. `localStorage` всегда в try/catch.
9. **Простота.** Без ECS, DI-контейнеров и глубоких иерархий классов. Функции и простые данные.

## Тесты

- Каждый примитив эффекта и каждая единица контента покрыты тестом симуляции.
- Генератор проверяется на 1000 сидов: все клетки пола достижимы, старт и выход связаны.
- Тест детерминизма: один сид и одна последовательность команд дают байт-в-байт одинаковое состояние.
- Найденный баг сначала воспроизводится тестом по сиду, потом чинится.

## Порядок работы над задачей

1. Прочитать `docs/GDD.md` и текущий этап в `docs/ROADMAP.md`.
2. Написать короткий план (5–10 пунктов) и дождаться подтверждения, если задача меняет архитектуру или дизайн. Обычную задачу выполнять сразу.
3. Реализовать небольшими коммитами с понятными сообщениями.
4. Перед сдачей прогнать `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`. Всё должно быть зелёным.
5. Закончить отчётом на русском: что сделано; как проверить (ссылка на превью, сид, шаги); что не сделано и почему; где отступил от GDD.
6. `CLAUDE.md` и `docs/GDD.md` не менять без явного согласия. Идеи и предложения складывать в `docs/PROPOSALS.md`.

## Отладка

- Параметры URL: `#seed-12345` задаёт сид, `#debug` включает дебаг-режим.
- Дебаг-меню по клавише `` ` ``: сид, FPS, вид сверху, а с соответствующих этапов выдача любой способности, предмета, дара, прыжок в любую комнату, бессмертие.
- Кнопка «Скопировать состояние»: сид и список команд в буфер. Игрок вставляет это в баг-репорт, и баг воспроизводится точно.
